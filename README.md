# Foundry Learning Loop Lab v1 · 한국어

**[브라우저에서 실습 시작 → GitHub Pages](https://junwoojeong100.github.io/foundry-evaluation-labs-v1/#start)**

설치 없이 가이드를 읽을 수 있습니다. 내려받은 패키지는 [index.html](index.html#start)을 열면 됩니다. GitHub Pages는 정적 문서만 제공하며 Azure 로그인·CLI 실행·유료 실습을 대신 수행하지 않습니다.

**참가자는 가이드 한 페이지의 6단계만 순서대로 진행합니다.** 문서나 실습 유형을 고를 필요가 없습니다.

> 예시 이해 → 환경 연결 → 기준선 평가 → Foundry IQ 지식 연결 → Agent Optimizer 지시 개선 → 최종 판정·종료

**예상 3–4시간, 결과 공유 포함**입니다. 기존 환경에서 교정을 통과해 핵심 경로를 끝까지 진행하는 계획값이며, 신규 환경 구축·SFT는 제외합니다. 가이드는 **기능 이해 → 실행 명령과 해설 → 출력 예시 → 내 결과 공유·판단 → 다음 단계**로 읽습니다. 예시는 설명용이며 실제 성공 기록이 아닙니다.

각 실습에 **경험할 기능·그 의미·중요한 이유·사용 방법**을 설명하고, 명령마다 옵션·입력·저장 파일·Azure 호출/비용·재실행 주의점을 붙였습니다. 처음 CLI를 쓰면 [02의 명령 읽는 법](index.html#cli-basics)부터 참고하세요.

**실제 Foundry Portal 스크린샷 14장**을 해당 단계와 SFT 부록에 넣었습니다. 사용자 인증 후 **Headless Playwright MCP**로 기존 프로젝트·배포·Agent·IQ·Optimizer·평가·MCP trace·SFT를 직접 열어 촬영했습니다. [프로젝트 화면](index.html#portal-project)부터 위치와 읽는 법을 따라가고 그림 아래의 원본 크기 링크로 확대할 수 있습니다. 설정 마법사는 미제출, 결과 사진은 기존 실행이며 개인정보·endpoint는 가렸습니다. 새 유료 실행을 한 기록은 아닙니다.

평가마다 **실제 결과 → 대표 사례 → 다음 결정**을 공유합니다. 채점자 교정, 기준선, IQ, Optimizer 추천, 개선 후보 재평가, 최종 새 질문 평가를 구별해 “왜 다시 평가하는지”를 경험합니다. 기존 보고서를 읽는 활동이며 평가 호출이나 외부 전송을 추가하지 않습니다.

`explain`은 저장된 결과의 **기준·점수·Judge 이유·HOLD 원인·개선 제안**을 연결해 보여 줍니다. 동일 문항의 비교에서는 설정된 회귀 허용폭도 로컬 계산합니다. 평가 전 루브릭, 평가 후 행동표와 완성 예시는 가이드 안에 있으며, 설명 명령은 기존 평가 파일이나 승인 상태를 변경하지 않습니다.

**기존 실습과 같은 환경입니다.** 이미 만든 전용 NCUS 리소스, Contoso 데이터, 모델과 평가 기준을 그대로 사용합니다. 안내 변경 때문에 재배포하거나 완료한 실험을 다시 실행하지 않습니다. 15개 장을 6단계로 묶고 기본 진행 경로를 명확히 한 것입니다.

## 시작 전에

패키지 **전체**를 같은 폴더에 둔 채 `index.html`을 엽니다. Python 3.11 이상이 필요하며 3.12를 권장합니다. 터미널은 macOS/Linux의 bash·zsh 또는 Windows WSL2 Ubuntu를 사용합니다.

상단 오른쪽의 **어둡게/밝게** 선택은 브라우저에 저장됩니다. **현재 인쇄**는 읽는 단계만, **전체 PDF**는 현재 문서 전체를 인쇄 창으로 엽니다. PDF로 저장을 선택하세요. 인쇄는 항상 밝은 배경이며 부록까지 포함한 통합 PDF 파일은 하단에서 열 수 있습니다.

첫 단계는 설치·Azure 로그인·SDK·네트워크·유료 호출 없이 읽고 실행하는 **AI 작성 DEMO**입니다. DEMO 뒤의 로컬 설치와 실행 명령은 가이드 안에 있습니다.

운영자는 LIVE 전에 참가자가 사용할 계정·권한·실습 환경·현재 비용 승인을 확인하고 비공개 환경 폴더를 전달합니다. **실습 환경이 아직 없을 때만** [운영자 사전 준비](admin.html)를 수행합니다. 기존 전용 환경이 있으면 원래 manifest로 연결하며 새 RG를 만들지 않습니다.

## 어디까지 하면 끝인가요?

| 단계 | 완료 시 남는 것 |
|---|---|
| 01. 예시 이해 | 환불 오답과 필요한 확인 질문에 대한 본인의 판단 |
| 02. 환경 연결 | 동일 실습 환경의 소유 확인·preflight와 원본 데이터 검사 |
| 03. 기준선 평가 | 실제 기준선 응답과 업무 Judge 교정 근거 |
| 04. 지식 연결 | IQ의 실제 검색·MCP 출력과 dev 12건 평가 |
| 05. 지시 개선 | Agent Optimizer 후보 1개와 같은 dev 사례의 전후 근거 |
| 06. 최종 판정·종료 | 동결·fresh12의 실제 결과 또는 미실행 이유, HOLD 판단과 보존 책임 |

**06에서 끝입니다.** Prompt Optimizer, 별도 managed 평가, SFT와 Frontier는 심화 자료에 남아 있지만 기본 완료 조건이 아닙니다. 오류·교정 불합격이면 유료 진행을 멈추고 근거와 미실행 항목을 기록합니다. 학습 완료, 실제 API 성공, 품질 통과, 사람의 운영 승인은 서로 다릅니다.

## 지켜야 할 경계

- 원본 정책 8개·데이터 100건과 train 56 / validation 12 / dev 12 / test 20을 유지합니다. 동결 후 fresh12는 별도 계약이며 기존 test20의 합격선을 낮추지 않습니다.
- 소유가 확인된 전용 **North Central US** 환경만 사용합니다. 무관한 기존/공유 자원·정책·다른 리전으로 우회하지 않습니다.
- 각 참가자의 실제 비용·데이터·작업 승인이 필요합니다. 기존 실행의 금액 무상한 승인을 재사용하지 않으며, 유한한 호출·작업·후보·대기 한도를 지킵니다.
- **자원과 원본 결과를 보존합니다. 삭제 승인은 없습니다.** 터미널 종료로 Search·로그·모델 호스팅 비용이 멈추지는 않습니다.
- AI 작성·검토는 AI로 표시합니다. 실패·점수·합격선을 바꾸거나 AI가 사람의 검토/승인을 대신 기록하지 않습니다.
- 비공개 환경·승인·자격 증명·가공 전 실행 결과는 소스, ZIP, PDF에 넣지 않습니다. 공개 증거는 정리된 [`evidence/`](evidence/integration-20260930/)만 사용합니다.

## 제작자용

현재 디렉터리와 [GitHub 저장소](https://github.com/junwoojeong100/foundry-evaluation-labs-v1)의 이름은 **`foundry-evaluation-labs-v1`**이며, 가이드 표기도 **v1**으로 통일합니다. 기존 개발 환경의 옛 경로는 가상환경·동결 기록의 절대 경로를 보존하는 호환용 링크이며 별도 복사본이 아닙니다. 신규 설치에서는 이 링크를 만들 필요가 없습니다.

```bash
python scripts/build_guide.py
python scripts/build_guide.py --check
python -m unittest discover -s tests -v
```

**명령 해설:** 첫 줄은 Markdown에서 등록된 HTML과 통합 인쇄 HTML을 생성합니다. `--check`는 쓰기 없이 생성물이 원문과 같은지 확인합니다. 마지막 줄은 `tests/`의 자동 검사를 자세한 출력(`-v`)으로 실행합니다. 모두 로컬 제작 명령이며 Azure 실습 성공이나 PDF 재생성을 대신하지 않습니다. 포털 사진을 갱신하면 `web/assets/portal/captures.json`의 출처·가림 범위·치수·해시도 함께 갱신합니다.

HTML·인쇄본은 빌더로 생성하며 PDF·ZIP은 별도 재생성합니다. `python -m lab`는 이 저장소의 교육용 도구이며 Microsoft 공식 CLI가 아닙니다. 가이드는 **v1**, 문서 기준일은 **2026-09-30**입니다.

**온라인 게시:** GitHub Pages의 소스는 `main` 브랜치의 `/ (root)`입니다. 루트의 `.nojekyll`로 Jekyll 변환 없이 생성된 `index.html`과 상대 경로 자산을 그대로 제공합니다. 원문 수정 후 HTML·PDF를 갱신해 커밋·푸시하면 Pages에 반영됩니다. 저장소 공개는 `.lab/`·인증·승인·가공 전 실행 결과의 공개나 별도 Azure 접근 권한을 의미하지 않습니다.
