실습 안내서 문서 기준 2026-10-01

강사 안내 · 실제 측정 결과 개선하기

참가자 6단계 · 운영자 인수 · 최신 v2 검증

자사 업무 과제와 실제 관리형 평가로 평가 → 학습 → 개선 → 재평가를 설명합니다. 약한 기준선을 인위적으로 만들거나 앞으로의 모든 평가가 개선된다고 약속하지 않습니다.

수업 전

운영자가 contoso-eval-en-sol, Sol 모델 배포, 기존 읽기 전용 정책 도구, 등록된 영어 dev12, Luna Judge와 지원되는 gpt-5.5 Optimizer 배포를 제공합니다. 운영자 가이드에서 모델 역할·신원을 확인합니다.

v1·v2는 변경 불가능한 Agent 전체 구성 버전입니다. 모델·도구·추론·엄격한 출력 스키마는 같고 지침만 다릅니다. v1부터 근거·분류·날짜·불확실성 지침을 갖추며, 후보 개발은 정식 버전을 계속 늘리는 대신 초안으로 진행합니다.

영어·한국어 데이터와 Agent를 분리합니다. 한국어 가이드는 절차를 설명하며 현재 공개된 실측은 영어 데이터 결과입니다.

참가자 단계는 정확히 여섯 개

단계 필수 동작 완료 근거
01 데이터셋 변경 없는 세 열 JSONL과 기존 등록 확인 12행 전체, 버전·SHA-256
02 평가기 Relevance 1–5점·임계값 4, TaskAdherence 이진 0/1·통과 1, Luna Judge 저장된 원격 정의와 query 전용 입력
03 기준선 고정 Sol v1에 실제 Foundry Evaluation 완료된 run ID와 전체 결과
04 분석 실제 답변·점수·이유·정책 읽기 실패를 포함한 구체적인 개선 가설
05 최적화 실제 instruction-only Agent Optimizer와 지침 diff 실제 job/candidate ID, 지침 외 설정 불변
06 재평가 같은 정의·데이터·Judge로 명시적 후보 실행, Compare runs 행별 대응 근거, 개선 검사와 정직한 판단

Individual turns / One time / Existing dataset을 사용합니다. 업로드 미리 보기가 5행이어도 실험은 12행입니다. 버전 선택으로 체크박스가 해제되면 다시 선택하고 대상 한 개를 확인합니다.

실제 사례로 토론

질문 → 실제 답변 → 평가 점수·이유 → 정책·참고 답변을 연결합니다. conversation_id → User view는 대화이며 평가 이유는 Detailed metrics result의 Relevance.reason·TaskAdherence.reason에서 확인합니다.

약한 사례와 잘한 사례를 하나 이상 토론합니다. 실패가 없다면 최저점 사례를 사용하며 실패를 관측하지 못했다고 말합니다. v1을 약화하거나 어려운 행·참고 답변을 바꾸거나 로컬 점수로 대신하지 않습니다.

최신 공개 기록은 합성 질문 12건, 두 실제 응답과 관리형 평가 이유를 포함합니다. 평가 결과는 자격 증명이 아닙니다. 제외할 것은 토큰·쿠키·서명된 URL·비공개 계정 정보이지 실패 결과가 아닙니다.

개선 해석

Relevance 4/5는 정확도 80%가 아닙니다. TaskAdherence 1은 통과이지 5점 중 1점이 아닙니다. 지표별 점수·통과 건수, 전체 기준 통과, 오류·평가 범위를 구분합니다.

scripts/compare_foundry_eval.py는 전체 사례 대응, 데이터·모델·도구·설정 일치, 실제 행별 버전·지침, 통과 건수·평균의 비회귀와 하나 이상의 명확한 관측 개선을 요구합니다. 잘못된 JSON을 고쳐 통과로 바꾸지 않고 실패로 남깁니다.

범용 평가기가 통과시켜도 근거 없는 확신, 정책 계산 오류, 실행 완료 주장과 잘못된 분류를 직접 읽습니다. 불가능한 확답을 요구한다고 사실을 만들어내면 안 됩니다.

Optimizer 내부 순위는 후보 선택 근거이지 별도 관리형 재평가의 평균·통과율과 같은 값이 아닙니다. 순위 상승만으로 더 나은 v2가 입증되지 않습니다.

실험 조건을 바꾸지 않는 복구

증상 대응
다른 신원, 401/403 승인된 계정·프로젝트 확인, 공유 권한 확대 금지
카탈로그·배포 성공 후 Agent 실패 실제 API·런타임 오류를 남기고 해당 역할 확인
포털 Add run item-schema 오류 기존 기준선 data source의 공식 SDK helper 사용, 다른 채점기로 대체 금지
No custom evaluators available Custom only OFF 또는 View built-in evaluators
로컬 receipt·같은 이름의 원격 run 존재 같은 run 재조회, 이름 변경을 통한 중복 제출 금지
후보가 모델·도구·추론·스키마 변경 지침만의 비교라고 주장하지 않음
초안 요청이 정식 번호로 생성 기대한 초안 지원이 아니므로 중단
기존 v2와 소스 불일치 덮어쓰기·v3 생성 금지, 원본 보존 후 확인
결과·점수 누락 부분 실행으로 표시하고 분모를 줄이지 않음
통계 비교 Inconclusive 그대로 보고하며 유의성·동등성을 주장하지 않음

Relevance는 {{sample.output_text}}, TaskAdherence는 {{sample.output_items}}를 사용합니다. 서비스 생성 매핑을 덮어쓰거나 ground_truth를 Agent에 주입하지 않습니다. 오래된 로컬 기본값보다 원격 평가의 실제 Judge가 우선입니다.

흔한 오해 바로잡기

주장 설명
“v2는 지침 파일 번호일 뿐이다.” Agent 전체 버전이며 이번에는 지침만 바꿈
“새 모델 v2를 옛 모델 v1과 비교하면 된다.” 지침 효과를 비교하려면 두 버전의 모델이 같아야 함
“실행 전에 반드시 개선된다고 보장한다.” 실측 개선은 확인할 수 있지만 향후 확률적 결과는 보장할 수 없음
“성공한 행만 남긴다.” 실패·오류·누락까지 전체 사례를 남김
“스키마가 올바른 업무 판단을 인증한다.” 구조를 제한할 뿐 정책 사실·분류까지 보장하지 않음
“공개 근거에 쿠키·원본 로그가 필요하다.” 합성 실응답·이유를 허용 필드로 공개하고 인증 정보는 제외

현재 보고서 하나로 마무리

오래된 버전별 보고서를 누적하는 대신 최신 v2 검증과 고정 v1 대조군을 공개합니다. 과거 원본 receipt는 감사용으로 보존하며 최신 쌍의 결과로 바꾸어 표시하지 않습니다.

동일 모델 비교 결과, 서비스 통계 검정, 지연·토큰 상충 관계와 합성 dev 재사용의 한계를 보고합니다. 후보 활성화는 운영자의 별도 결정이며 운영용 게시를 이번 실습에 포함하지 않습니다.
